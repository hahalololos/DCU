# Qwen3.5 专用 UA2D 快速榜单提交设计

时间：2026-07-12 10:02

## 目标

以当前 `vllm_cscc` 提交 `c274c6b` 为候选版本，不再叠加新的 kernel 优化。先用 4B 完成快速端到端门禁，再对 27B 做最小必要的形状适配与正确性验证，通过后直接提交榜单，尽快兑现尚未进入榜单的 Qwen3.5 专用 UA2D 收益。

本轮不是探索新的优化方向。最新榜单提交基于 `39c4654`，尚未包含后续专用 UA2D 提交 `5bf55cb`、`882f326` 及清理提交 `515ec50`、`c274c6b`。

## 候选优化

候选保留专用 `kernel_qwen35_unified_attention_2d`，核心配置固定为：

- `TILE_SIZE=32`
- `BLOCK_M=32`
- `num_warps=4`
- `num_stages=1`
- 标量 block-table 地址计算

专用路径只允许已验证的 gfx936、BF16、head size 256、4 KV heads、causal prefill，以及 Qwen3.5-4B `(16,4,4)` 或 Qwen3.5-27B `(24,4,6)` 形状；其余情况回退通用实现。

已有依据：代表形状 `q=4096/kv=22258` 的单 kernel 延迟由约 `52.0 ms` 降至约 `44.8 ms`，加速约 `14.1%`。4B 热态端到端复测中，中档请求吞吐约提升 `4.65%`，长档约提升 `4.8%`，对应 TTFT 分别下降约 `6.34%` 和 `6.9%`。

## 验证流程

### 1. 环境与源码确认

- 每次远端操作先加载 `.venv` 和 `env.sh`。
- 检查 GPU、端口与队友进程，确保测试不受并发服务污染。
- 同步本地 `vllm_cscc` 到远端，并核对候选关键文件 SHA256。
- 确认 `which python`、`which vllm` 和 `pip show vllm` 均指向规定虚拟环境及源码树。
- 本轮仅涉及已有 Python/Triton 路径，不新增 HIP/C++ 扩展构建。

### 2. 4B 快速门禁

使用官方 4B 模型和现有测试脚本，对 4–8K、8–16K、16–32K 三档各运行 10 条热态请求。对照版本采用原 UA2D fastpath，候选采用当前专用 UA2D；两组保持其余源码、模型、参数和环境一致。

记录：

- 完成请求数；
- request throughput 和 output throughput；
- TTFT P99；
- TPOT P99；
- 输入、输出 token 总数；
- 是否存在冷编译、外部并发或代理污染。

4B 通过条件：

1. 三档均完成 `10/10`。
2. 8–16K 或 16–32K 至少一档的请求吞吐稳定提升不低于约 `3%`。
3. 另一重要档位不得出现超过约 `2%` 的可重复请求吞吐回退。
4. TPOT P99 不得出现超过约 `2%` 的可重复恶化。
5. 若数据受队友服务、冷编译或显存残留污染，该轮作废，不据此回滚候选。

短档允许小幅波动，但若出现超过约 `3%` 的稳定回退，需要结合 20% 档位权重估算总分影响后再决定是否提交。

### 3. 精度取舍

已有同一 109 条 4B 重放结果显示，TILE32 相对原 fastpath：hotpotqa、retrieval 和 aggregation 不变，gov_report 约下降 `2.00%`。本轮沿用已经确认的吞吐优先决策，不重复完整 4B 精度评测，除非端到端输出变化明显超出既有结果。

不得扩大专用 guard、改变模型推理语义、修改采样或评测参数，也不得加入任何测试集特化逻辑。

### 4. 27B 最小提交门禁

4B 通过后，27B 不等待完整三档长时间基准，只完成提交前必要验证：

1. 确认专用 guard 对 27B `(24,4,6)` prefill 形状实际命中。
2. 运行现有 27B 定向正确性用例，覆盖短 query、长 query、非整块 query、cache-block 边界和 GQA=6 padding。
3. 候选与通用路径满足既有误差门限，并检查重复运行确定性。
4. 若资源窗口允许，优先补一轮 8–16K 端到端测试；该项用于增强信心，但不是提交硬门槛。

如果 27B 模型因共享存储加载缓慢而无法及时完成端到端测试，只要定向正确性、guard 命中和 4B 门禁均通过，即按本设计提交榜单。

## 异常处理与回滚

- 发现 GPU 并发占用、异常显存残留或端口冲突时，只停止本工作区进程，不影响队友服务。
- 若 PRA26 容器不可达，按项目规则检查作业状态；容器未运行时停止远端操作并请用户处理。
- 若 4B 门禁确认中长档回退，回滚至榜单提交 `39c4654`，不带病提交。
- 若 27B 正确性失败，先回滚本轮提交，不临时放宽误差门限或 guard。

## 提交与结果判定

提交物仅包含 `vllm_cscc` 源码。提交前记录当前提交哈希、远端验证结果和关键环境信息，并更新 `docs/progress.md`。

榜单结果按以下顺序判断：

1. SLA 扣分必须为 0。
2. 完成率不得下降。
3. 优先观察权重最高的 8–16K，其次观察 16–32K。
4. 总分需高于当前 `77.8753` 才视为本轮有效收益。
5. 若中长档收益符合预期，下一轮进入 UA3D decode KV-load 优化；若长档未改善或回退，下一轮优先拆分 LLMM1 shape filter。

## 范围外事项

本轮不实施 UA3D 新优化、不继续拆分 LLMM1 shape filter、不修改 scheduler、测试脚本、模型、权重、tokenizer、chat template 或锁定参数，也不进行 27B 全三档长时间性能搜索。
