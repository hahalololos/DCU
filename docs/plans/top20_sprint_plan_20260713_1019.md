# Qwen3.5 推理服务 Top 20 冲刺执行计划

生成时间：2026-07-13 10:19 CST

## 1. 当前基线与目标

当前版本以 `vllm_cscc` 提交 `d609979` 为基线。后续不再投入已经证明无法传导到端到端的
GDN 小 kernel 调参，主线集中到 Decode Linear、UA3D 和 UA2D。

## 2. 总体执行顺序

1. 固定并复测当前 27B 基线，获得正式 prefill/decode profile。
2. 优先优化 Decode Linear/GEMV，补齐短、中档吞吐。
3. 优化 UA3D 的 KV 读取与分段合并，补齐中、长档。
4. 若仍未达到安全线，再进行 UA2D LDS/VGPR 结构优化。
5. 每个胜出候选独立提交、三档回归、精度门禁，最后组合验证并提交榜单。

## 3. 阶段 A：27B 基线与热点定量

### 工作内容

- 按项目约定同步本地 `d609979` 到 `scnet-docker-1`。
- 检查 Python、vLLM、源码导入位置、GPU、端口及遗留进程。
- 启动正式 27B，跑三档各 10 条基线；保存吞吐、P99 TTFT/TPOT、完成率和输出。
- 对三档代表请求分别采集 prefill 与稳定 decode trace。
- 汇总 Linear/GEMV、UA3D、UA2D、GDN、launch/其他 kernel 的时间占比。
- 对 Decode Linear 列出前五个热点的准确 `(M,N,K)`、调用次数、单次耗时和累计占比。

### 产物与门禁

- 实验编号：`TOP20-A0-27B-BASE`、`TOP20-A1-27B-PROFILE`。
- 三档必须 `10/10` 完成，精度/SLA 预期不变。
- 若 Linear 占稳定 decode 时间 `>=50%`，进入阶段 B；否则按 profile 在 B/C 中重新排序。

## 4. 阶段 B：Decode Linear/GEMV 专用化

### B1：形状扫描和实现选择

优先扫描 27B 的大 K、小 N 热点，特别是 MLP down、gate/up、LM head 和 attention output。
对每个 Top 形状比较：

- 当前 dispatch（LLMM1/Skinny/F.linear）。
- rocBLAS/hipBLASLt 可用算法。
- gfx936 BF16 专用 GEMV 原型。
- `N=1`、小 batch 以及实际并发 batch 的分开 dispatch。

专用 kernel 优先优化权重连续加载、wave 间 K 维分工、局部累加和低成本归约；严格限定
gfx936、BF16、已验证形状，未命中时回退现有路径。

### B2：筛选门槛

- 单形状 micro 中位数提升 `>=15%`，累计 decode 预测收益 `>=2%` 才接入生产路径。
- 数值满足现有 BF16 Linear 标准，无 NaN/Inf，重复执行稳定。
- 4B 只做正确性和快速烟测；最终取舍以 27B 端到端为准。
- 27B 至少短或中档提升 `>=3%`，其他档稳定回退不得超过 `1%`。

### 停止条件

若 Top 形状可实现的累计端到端预测收益低于 `2%`，停止继续写 GEMV，直接进入阶段 C，
避免重复 GDN“micro 好看但端到端无收益”的路径。

## 5. 阶段 C：UA3D Decode Attention

### 候选顺序

1. Profile 当前 scalar block-table 胜出版本，分离主 kernel 与 merge kernel成本。
2. 针对 27B `block_size=784/head_size=256/kv_heads=4` 优化连续 KV 加载和地址生成。
3. 降低 VGPR 存活区间，提高 occupancy。
4. 若 merge kernel 与中间状态写回占比明显，原型化单 kernel/协作式 merge；否则不做。
5. segments 仅做 `8/16/32` 小范围复核，不再进行大规模盲扫。

### 门槛

- UA3D 两 kernel 总时间提升 `>=15%`。
- 27B 中档或长档端到端提升 `>=2%`，其他档回退不超过 `1%`。
- 覆盖 `783/784/785` cache-block 边界以及 8K/16K/32K 数值测试。

## 6. 阶段 D：UA2D Prefill 结构优化

仅当完成 B/C 后长档仍低于 `14.0`，或 UA2D 仍占长档 prefill GPU 时间 `>=40%` 时启动。

### 候选顺序

1. 测量专用 UA2D 的 VGPR、LDS 和 bank conflict，定位冲突数组及访问步长。
2. 调整 LDS padding/转置布局，优先以最小改动降低 bank conflict。
3. 缩短 softmax `M/L/acc` 和地址状态的存活区间，降低 VGPR。
4. 将 full-prefix 与 causal diagonal 拆成更专用的执行阶段；仅在状态合并成本可控时拆 kernel。

### 门槛

- UA2D 热点 kernel 提升 `>=10%`。
- 27B 长档端到端提升 `>=3%`，中档不得稳定回退。
- GQA=6、非完整 query block、`783/784/785` 边界全部通过。

## 7. 组合验证与榜单提交

每条主线只保留通过门禁的独立提交，随后按以下顺序组合：

1. 当前基线 + B。
2. 当前基线 + B + C。
3. 如有必要，当前基线 + B + C + D。

最终候选必须完成：

- 27B 三档各 10 条，完成率 100%。
- 相同输入顺序的 baseline/candidate A/B。
- 四类精度验证，平台预期精度扣分为 0。
- P99 TTFT/TPOT 无异常长尾，SLA 扣分为 0。
- 源码、环境变量、提交 hash、实验目录全部可复现。

达到 `88.0+` 或三档安全目标后提交；若仅刚好超过当前第 20 名但低于 `87.8`，继续保留一次
优化/提交余量，避免排行榜自然上涨导致再次跌出 Top 20。
