# 合规边界清单

本清单依据赛题技术方案整理，用于在后续设计优化方案时快速判断是否能做。原则：凡是改变模型有效计算结构、权重、输入输出语义、评测接口或统计口径的方案，默认禁止；凡是只改变推理期内部执行效率且不生成可复用作弊产物的方案，优先视为可研究。

## 1. 可做项

| 优化项 | 状态 | 依据条款 | 原因 | 需要确认的问题 |
| --- | --- | --- | --- | --- |
| KV Cache 分配机制优化 | 允许 | 第 3/5/6 条 | 赛题明确鼓励 KV Cache 与显存管理优化 | 是否允许改 vLLM hybrid KV cache group 的内部实现细节 |
| PagedAttention block 粒度、对齐、回收策略 | 允许 | 第 5/6 条 | 赛题点名高效块管理与碎片化控制 | `--block-size` 若被评测脚本锁定，只能改内部实现，不能改外部参数 |
| 显存预算控制 | 允许 | 第 6 条 | 赛题允许优化显存预算控制和资源组织 | 不能通过预算限制导致跳过请求或降低完成率 |
| Decode Attention kernel 优化 | 允许 | 第 5 条 | 赛题明确允许生成阶段 Attention 算子优化 | 需保持标准自回归解码语义 |
| Decode Linear/GEMM 优化 | 允许 | 第 5 条 | 赛题明确允许 Linear 算子优化 | 需验证 bf16/临时低精度误差对精度的影响 |
| 算子融合 | 允许 | 第 5 条 | 可降低 kernel launch 和访存开销 | 不能融合掉必要计算或改变数值路径到明显影响精度 |
| Python 调度开销削减 | 允许 | 第 5 条 | 赛题允许执行路径优化 | 不得修改被锁定的 batch scheduler 相关参数或调度语义 |
| 内存拷贝路径优化 | 允许 | 第 5/6 条 | 属于执行路径和数据搬运开销优化 | 需确认是否涉及服务接口或统计路径 |
| custom kernel | 允许 | 第 4 条 | 允许安装 Python 包、编译 custom kernel，但需说明 | 评测期禁止联网下载依赖，必须随源码提交 |
| 推理过程中的激活动态量化 | 允许 | 第 7 条量化边界 | 明确允许非持久化、算子级低精度计算优化 | 必须验证四类任务精度下降 |
| KV Cache 量化 | 允许 | 第 7 条量化边界 | 明确允许 KV Cache 量化 | 不得生成可复用量化权重或缓存文件 |
| kernel 内部临时类型转换 | 允许 | 第 7 条量化边界 | 明确允许 kernel 内部临时转换 | 需确认 DCU 支持类型和累加精度 |
| 低精度矩阵乘法 | 允许 | 第 7 条量化边界 | 明确允许非持久化低精度矩阵乘法 | 不能预先改权重格式或生成量化权重缓存 |
| profiling 与日志采集 | 允许 | 第 14 条 | 优化说明文档建议提供性能对比数据 | 日志不能伪造或隐藏异常 |

## 2. 禁止项

| 优化项 | 状态 | 依据条款 | 原因 | 需要确认的问题 |
| --- | --- | --- | --- | --- |
| 修改模型权重 | 禁止 | 第 7 条 | 严禁替换或修改权重 | 无 |
| 模型持久化量化 | 禁止 | 第 7 条量化边界 | 禁止加载前/加载后/初始化阶段/正式推理前进行持久化量化 | 无 |
| 权重重排压缩或格式转换 | 禁止 | 第 7 条量化边界 | 禁止生成可复用压缩权重或格式转换产物 | 无 |
| 模型图重构 | 禁止 | 第 7 条量化边界 | 可能改变模型结构或评测语义 | 需确认纯执行图优化是否被视作重构；默认不碰 |
| 结构化/非结构化剪枝 | 禁止 | 第 7 条剪枝边界 | 明确禁止 | 无 |
| 动态通道跳过、动态层跳过 | 禁止 | 第 7 条剪枝边界 | 改变有效计算结构 | 无 |
| attention head 裁剪 | 禁止 | 第 7 条剪枝边界 | 改变模型结构 | 无 |
| token pruning | 禁止 | 第 7 条剪枝边界 | 改变输入上下文有效计算 | 无 |
| early-exit | 禁止 | 第 7 条剪枝边界 | 改变标准自回归解码流程 | 无 |
| 投机解码、draft model、MTP | 禁止 | 第 9 条不允许调整参数 | 明确禁止任何形式投机解码 | Qwen config 中存在 `mtp_num_hidden_layers`，比赛方案不得启用相关推理能力 |
| 外挂小模型、自训练预测器 | 禁止 | 第 7/9 条 | 属于题目规定外辅助模型 | 无 |
| 预缓存测试集、答案、中间结果 | 禁止 | 第 7 条 | 针对性作弊 | 无 |
| 跳过长样本、过滤困难样本 | 禁止 | 第 7 条 | 规避真实推理开销 | 无 |
| 截断输入 | 禁止 | 第 7 条 | 改变任务定义 | 无 |
| 强行调低 `max_tokens` | 禁止 | 第 7/9 条 | 改变输出行为 | 无 |
| 修改 tokenizer 或 chat template | 禁止 | 第 4/9 条 | 统一 tokenizer 与官方 chat template | 无 |
| 绕开 OpenAI API 服务接口 | 禁止 | 第 7/9 条 | 评测接口固定 | 无 |
| 修改 bench 统计口径或结果解析 | 禁止 | 第 9 条 | 评测口径锁定 | 无 |
| 评测期联网下载依赖 | 禁止 | 第 4 条 | 统一容器不注入额外库，禁止外网依赖 | 无 |

## 3. 高风险待确认项

| 优化项 | 状态 | 依据条款 | 原因 | 需要确认的问题 |
| --- | --- | --- | --- | --- |
| 修改 vLLM batch scheduler 内部逻辑 | 风险 | 第 9 条 | 文档写明不允许 batch scheduler 相关参数及内部代码修改 | 单请求固定并发下，是否允许只剪掉无效分支而不改变调度语义 |
| 开启 prefix caching | 风险 | 第 7/9 条 | 容易被误判为预缓存或针对样本复用；单请求盲测也收益有限 | 官方是否锁定该参数，是否允许自动 prefix cache |
| 调整 `--max-num-batched-tokens` | 禁止/风险 | 第 9 条 | 明确列为不可调整项 | 若内部默认值由平台脚本设定，不能覆盖 |
| 修改 `--block-size` 启动参数 | 风险 | 第 5/9 条 | KV 块粒度是优化点，但外部参数可能被锁定 | 是否只能改内部策略，不能改命令行参数 |
| 修改服务启动环境变量 | 风险 | 第 13 条 | 可用但必须提交环境变量说明 | 是否被平台白名单限制 |
| 使用第三方 HIP kernel 代码 | 风险 | 第 15 条 | 可用但必须标注知识产权来源 | 许可证是否兼容提交要求 |
| 使用 FP8/INT8 等临时计算 | 风险 | 第 7 条 | 允许非持久化低精度，但精度和 DCU 支持需验证 | 是否支持对应 DCU 指令和库；精度下降是否超过 1%/2% |
| 修改采样后处理路径 | 风险 | 第 9 条 | 可能影响输出 token 或 streaming 时序 | 只能优化实现，不能改采样参数和输出语义 |

## 4. 后续执行守则

1. 每个优化 PR/实验必须先在本清单中标注合规状态。
2. 任何可能影响输出内容的优化必须同步跑 OpenCompass 精度。
3. 任何可能影响 TTFT/TPOT P99 的优化必须至少跑三档 `vllm bench serve`。
4. 禁止用“对本地样本有效”作为优化依据，必须面向长度档位和通用路径。
5. 使用第三方代码、算法或库时，在优化说明文档和 `README.md` 头部登记来源。
