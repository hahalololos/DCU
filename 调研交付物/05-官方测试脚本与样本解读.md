# 官方测试脚本与样本解读

本文件基于比赛方提供的 `testdata/` 目录整理。该目录包含 3 个脚本和 7 个 jsonl 样本，可作为第一轮 baseline 与精度回归的官方样例入口。

## 1. 目录内容

| 文件 | 行数 | 作用 |
| --- | ---: | --- |
| `start_vllm.sh` | - | 启动 vLLM 服务 |
| `run_throughput.sh` | - | 跑三档吞吐与时延 |
| `run_accuracy.sh` | - | 跑 OpenCompass 精度 |
| `4-8K_throughput.jsonl` | 50 | 4-8K 吞吐样本，字段为 `prompt` |
| `8-16K_throughput.jsonl` | 50 | 8-16K 吞吐样本，字段为 `prompt` |
| `16-32K_throughput.jsonl` | 50 | 16-32K 吞吐样本，字段为 `prompt` |
| `hotpotqa.jsonl` | 20 | QA 精度样本，LongBench 口径 |
| `gov_report.jsonl` | 30 | 摘要精度样本，LongBench 口径 |
| `retrieval_multi_point.jsonl` | 30 | 检索精度样本，RULER 风格 |
| `aggregation_keyword_aggregation.jsonl` | 30 | 聚合精度样本，RULER 风格 |

## 2. 运行方式

所有脚本都使用相对路径，建议从 `testdata` 目录执行：

```bash
cd testdata
bash start_vllm.sh
```

另开终端运行吞吐：

```bash
cd testdata
bash run_throughput.sh all
bash run_throughput.sh 8-16K 10
```

运行精度：

```bash
cd testdata
bash run_accuracy.sh all
bash run_accuracy.sh hotpotqa 5
```

第二个参数是样本数，适合冒烟测试。

## 3. 服务启动参数

`start_vllm.sh` 当前使用：

```bash
vllm serve "$MODEL_DIR" \
  --served-model-name Qwen3.5-27B \
  --port 8001 \
  --trust-remote-code \
  --dtype bfloat16 \
  --tensor-parallel-size 1 \
  --max-num-seqs 128 \
  --max-num-batched-tokens 4096 \
  --gpu-memory-utilization 0.95 \
  --default-chat-template-kwargs '{"enable_thinking": false}' \
  --reasoning-parser qwen3 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder
```

注意点：

1. `MODEL_DIR` 默认是 `../Qwen3.5-27B`。
2. 服务端口固定为 `8001`。
3. `--served-model-name` 固定为 `Qwen3.5-27B`，bench 和 OpenCompass 都依赖这个名字。
4. 显式关闭 thinking：`{"enable_thinking": false}`。
5. 脚本未显式设置 `--max-model-len 32768`，但赛题技术方案示例写过该参数。正式提交前必须确认平台最终启动命令。

## 4. 吞吐脚本口径

`run_throughput.sh` 使用 `vllm bench serve`，核心参数：

| 参数 | 值 |
| --- | --- |
| backend | `openai-chat` |
| endpoint | `/v1/chat/completions` |
| host/port | `127.0.0.1:8001` |
| model | `Qwen3.5-27B` |
| tokenizer | `$MODEL_DIR` |
| dataset-name | `custom` |
| max-concurrency | `1` |
| request-rate | `1` |
| temperature | `0` |
| custom-output-len | `1024` |
| num-warmups | `2` |
| percentile-metrics | `ttft,tpot,itl,e2el` |
| metric-percentiles | `50,95,99` |
| result filename | `result.json` |

结果路径：

| 档位 | 命令参数 | 结果文件 |
| --- | --- | --- |
| 4-8K | `bash run_throughput.sh 4-8K` | `test/4-8K_throughput/result.json` |
| 8-16K | `bash run_throughput.sh 8-16K` | `test/8-16K_throughput/result.json` |
| 16-32K | `bash run_throughput.sh 16-32K` | `test/16-32K_throughput/result.json` |

## 5. 精度脚本口径

`run_accuracy.sh` 会生成临时目录 `accuracy_debug/`，并动态写入 OpenCompass 配置：

| 项 | 值 |
| --- | --- |
| API | `http://127.0.0.1:8001/v1` |
| model path | `Qwen3.5-27B` |
| model abbr | `Qwen3.5-27B-vLLM` |
| API key | `EMPTY` |
| temperature | `0` |
| query_per_second | `1` |
| max_seq_len | `32768` |
| batch_size | `2` |
| postprocessor | `extract_non_reasoning_content` |

数据集：

| 数据集 | reader/evaluator | max_out_len | 备注 |
| --- | --- | ---: | --- |
| `hotpotqa` | LongBench HotpotQA 配置 | 1024 | QA |
| `gov_report` | LongBench GovReport 配置 | 1024 | 摘要 |
| `retrieval_multi_point` | `CustomDataset` + `AccEvaluator` | 96 | 脚本重算 exact match |
| `aggregation_keyword_aggregation` | `CustomDataset` + `AccEvaluator` | 128 | 脚本重算列表匹配 |

最终脚本会打印：

```text
===== Final Accuracy Results =====
| dataset | version | metric | mode | Qwen3.5-27B-vLLM |
...
output_dir: ...
```

## 7. 对调研方案的影响

1. baseline 文档应以 `openai-chat` + `/v1/chat/completions` 为准，不再使用通用 `/v1/completions` 模板。
2. 第一轮性能指标应直接读取 `test/*/result.json`。
3. 精度回归优先跑脚本自带的四个数据集，尤其是低精度或 sampling 路径优化后。
4. `run_throughput.sh` 的 `--request-rate 1` 与赛题“并发固定 1”一致，但不是最大压测的 `inf` 模式；后续若平台最终脚本不同，应以最终脚本为准。
5. `start_vllm.sh` 未显式设置 `--max-model-len 32768` 是当前最大待确认点。
